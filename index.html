Zoom out

Five threads kept crossing

History did not march neatly upward. Each layer solved a real pain, then created the next one.

HTML

Browser document → server-made page → client-made interface → server rendering returns. The pendulum moves toward whichever side can make the experience simpler or faster.

JavaScript

Hand-written DOM calls → jQuery shortcuts → whole-app frameworks → React components → more work handed back to capable browser APIs.

Build

None → task runners such as Grunt (2012) and Gulp (2013), which ran ordered lists of file jobs → webpack’s bundler era, which instead followed each file’s own imports to package an application’s connected pieces → Vite’s fast dev server and native ES modules.

Language

JavaScript stayed the language browsers run. TypeScript won the typing race by catching many mistakes when teams run a type check, then producing ordinary JavaScript for the browser.

CSS aside

Hand-written CSS grew Sass variables and nesting, then utility systems such as Tailwind traded named styles for small classes composed in HTML. Native CSS later absorbed variables, nesting, and more.

The rest of the iceberg

This page followed one thread

We tracked how browser code built one interface. A production web app is also a delivery network, a data system, a security boundary, and an operating practice. Each row below could be its own “through the years” guide.

Hosting + edge

Deployment turns files into a public service. A CDN—content delivery network—keeps copies near visitors; edge functions can run small pieces of server code near them too.

VercelFramework-aware deployments, preview URLs, and globally distributed delivery.
NetlifyGit-centered deploy workflows, atomic releases, previews, functions, and edge functions.
CloudflareCDN, DNS, security, Pages, Workers, and data services on one global network.

Next guide: Vercel vs Netlify vs Cloudflare—where does the app actually run?

Servers + APIs

A server validates requests, applies business rules, talks to private systems, and returns HTML or data. It might be one long-running program, a container, a serverless function, or code distributed across the edge.

What changed from one server in a rack to functions started per request?

Data + storage

Our specimen forgets on reload. Real apps choose databases for structured records, object storage for files, caches for speed, queues for work that can finish later, and backups for the day something breaks.

Where does the to-do live, and what happens when two people edit it?

Identity + security

Authentication asks who you are; authorization asks what you may do. Around them sit HTTPS/TLS encryption, secrets, input validation, security headers, dependency review, firewalls, rate limits, and protection from abusive traffic.

A login box is the visible inch of a much larger trust system.

DNS + requests

Before any HTML arrives, DNS turns a domain name into a destination. HTTP carries the request; TLS protects it; load balancers, proxies, caches, and CDNs decide which machine—or nearby copy—answers.

What happens between pressing Enter on a URL and seeing the first pixel?

Quality + operations

Tests catch regressions; accessibility work keeps the interface usable; continuous integration checks each change; observability combines logs, metrics, traces, and error reports so a team can understand failures after release.

Shipping is an event. Operating the app is the ongoing job.

These systems overlap. Modern platforms bundle several together, which is convenient until their defaults, limits, geography, pricing, or lock-in no longer match the app. The same tide appears again: assemble many primitives yourself, then adopt a platform, then split pieces apart when control matters.

And now: AI-assisted loops

AI can draft code, explain unfamiliar files, and shorten the edit–run–check loop. It is another layer, not a repeal of web history: someone still chooses the architecture, checks the browser, tests accessibility, and owns the mistakes. Expect the same tide—more abstraction now, then leaner tools as the useful parts settle into everyday practice.
